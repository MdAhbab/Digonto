# Overleaf package (drag and drop this folder)

Self-contained IEEE paper source. Nothing outside this folder is needed.

## Contents

| File | Purpose |
| --- | --- |
| `digonto.tex` | The paper. IEEEtran conference class, ~2,900 body words. |
| `references.bib` | 36 references, all 36 cited in the text, no orphans. Every DOI resolved and every URL fetched on 26 July 2026. |
| `figures/` | Empty on purpose. Figures 1 to 3 are TikZ inside `digonto.tex`, so there are no image assets to lose. Generated data plots go here later. |

## How to build

**Overleaf:** New Project, Upload Project, drag this folder in. Set the compiler to
pdfLaTeX and the main document to `digonto.tex`. `IEEEtran.cls` ships with Overleaf,
so no class file is needed. Overleaf runs BibTeX automatically.

**Local:**

```
pdflatex digonto
bibtex   digonto
pdflatex digonto
pdflatex digonto
```

## Why the figures are TikZ

Drag-and-drop uploads lose linked images more often than anything else, and a
missing `\includegraphics` target fails the build at submission time. Figures 1
to 3 are schematics (architecture, event delivery, promotion protocol), and the
project figure specification allows schematics to be drawn rather than generated
from data. Drawing them in TikZ makes this folder build with zero external files.

The one figure that is *not* allowed to be drawn by hand is the benchmark
before/after plot, because the figure specification requires data plots to be
generated by script from the raw result files. That figure is deliberately absent
until measurements exist. When the benchmark has been run, generate it into
`figures/` with the shared matplotlib settings block from
`writing_instructions.md` Part 3.6, and add it to Section V.

## Style rules this document follows

From `writing_instructions.md`: no em-dashes anywhere; no metaphors or figurative
language; every abbreviation explained in plain words at first use; sentences
kept under about 40 words; prose preferred over bullet lists; abstract kept
plain-text safe (no math, no special characters, "percent" spelled out) and under
200 words; no AI tool credited anywhere in the paper.

Every design target is labelled as a target, and Section V states in its first
sentence that it contains no measured results. Replace targets with measurements
before submitting to a venue, and regenerate the tables and figures in the same
run so the numbers cannot disagree.
