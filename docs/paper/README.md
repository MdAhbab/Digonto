# Overleaf package (drag and drop this folder)

Self-contained IEEE paper source. Nothing outside this folder is needed.

> **`digonto.tex` is on the development machine only.** `.gitignore` excludes
> `*.tex`, so the paper source is never published from this public repository.
> This README and `references.bib` are tracked, because a verified bibliography is
> useful on its own. If you clone this repository on another machine, the LaTeX
> file will not come with it. The readable mirror at `paper/research_paper.md` is
> tracked and carries the same text.

## How to build

**Overleaf:** New Project, Upload Project, drag this folder in. Set the compiler to
pdfLaTeX and the main document to `digonto.tex`. `IEEEtran.cls` ships with Overleaf,
so no class file is needed. Overleaf runs BibTeX automatically.

**Local:**

```
pdflatex digonto
bibtex   digonto
pdflatex digonto
pdflatex digonto
```

## Why most figures are TikZ, and two are not

Drag-and-drop uploads lose linked images more often than anything else, and a
missing `\includegraphics` target fails the build at submission time. The
three schematics (RC-RAG architecture, promotion protocol, event delivery)
draw fine in TikZ and need no image file, so they stay that way.

Two figures are real PNGs in `figures/`, because the project figure
specification requires a data plot to be generated by script from the raw
data, never drawn by hand: `fig02_refusal_trend.png` (Section I, reproduced
from the cited Schengen statistics source) and `fig06_latency_measured.png`
(Section V, the cold-load and warm-call latencies
`backend/tests/test_model_contracts.py` measured on the development machine).
Both ship with this folder, so an Overleaf upload still needs no external
fetch.

`fig07_agent_map.png` (which Gemma capability each agent uses) was generated
but is not referenced from `digonto.tex`. Its "Tools" and "Audio" columns mark
every agent as using native tool calling and mark Shonchari as using audio,
neither of which is true of the current build: every agent asks the model for
schema-constrained structured output rather than calling a tool, and voice
input is not implemented because no speech-to-text service is deployed.
Regenerate it with those two columns corrected before adding it to the paper.

The benchmark before/after plot (candidate adapter scores across promotions)
remains absent until that data exists. When the benchmark has been run,
generate it into `figures/` with the shared matplotlib settings block from
`writing_instructions.md` Part 3.6, and add it to Section V.

## Style rules this document follows

From `writing_instructions.md`: no em-dashes anywhere; no metaphors or figurative
language; every abbreviation explained in plain words at first use; sentences
kept under about 40 words; prose preferred over bullet lists; abstract kept
plain-text safe (no math, no special characters, "percent" spelled out) and under
200 words; no AI tool credited anywhere in the paper.

Every design target is labelled as a target. Section V now opens by separating
what live-model tests already verify (five contract tests, fifteen agent
tests, and the development-machine latency figures) from what remains a
protocol definition or a target. Replace the remaining targets with
measurements before submitting to a venue, and regenerate the tables and
figures in the same run so the numbers cannot disagree.
